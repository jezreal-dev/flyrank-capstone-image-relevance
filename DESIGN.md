# Architecture & Design Specification: AI Image Matching Engine

## 1. System Mission & Scope
The AI Image Understanding & Content Matching Engine ingests an image library, automatically extracts structured semantic attributes, generates vector embeddings, and pairs the most relevant image to incoming editorial articles.

The core differentiator is the **Mismatch Guard**: an automated safety verification layer that checks whether candidate images meet strict confidence, category alignment, and semantic relevance thresholds before recommending them. If no image qualifies, or if an image exhibits high semantic overlap but contradictory taxonomic categories (e.g., matching a wolf to an article on red foxes), the system explicitly refuses the match and emits a structured explanation.

---

## 2. Core Invariants & Decision Rules

1. **Structured Vision Ingestion**:
   - Every image processed produces a structured metadata payload validated against a strict schema.
   - Any image whose primary classification confidence falls below `0.70` is marked as `FLAGGED_LOW_CONFIDENCE` rather than accepted into active ranking.

2. **Semantic Matching Space**:
   - Article bodies and image descriptions (subject, caption, attributes) are mapped into a shared semantic vector space.
   - Matching evaluates conceptual relatedness rather than lexical token equivalence (e.g., mapping *Vulpes vulpes* to *Red Fox*).

3. **Mismatch Guard Invariants**:
   - **Threshold Cutoff**: Candidates with cosine similarity $< 0.60$ are marked `REJECTED_LOW_SIMILARITY`.
   - **Taxonomic / Subject Guard**: Even if cosine similarity is high, conflicting primary subjects (e.g., `wolf` vs. `fox`) trigger `REJECTED_CATEGORY_MISMATCH`.
   - **Default Refusal**: If zero candidates clear both the similarity and taxonomic checks, the engine returns `status: NO_CONFIDENT_MATCH` with diagnostic reasoning.

4. **Background Batch Ingestion**:
   - Bulk image tagging and embedding calculations execute asynchronously off the synchronous HTTP request path with retry capability and idempotency.

5. **Cost Attribution & Budget Guard**:
   - Every model invocation logs token usage, model identifier, and estimated expenditure.
   - An active ceiling prevents runs from exceeding safe budget limits.

## 3. Data Schema & Contracts

### 3.1 Structured Image Metadata Schema
```json
{
  "subject": "red fox",
  "category": "wildlife",
  "attributes": ["orange fur", "bushy tail", "forest", "canid"],
  "caption": "A red fox standing alert in a temperate pine forest",
  "confidence": 0.94
}
```

### 3.2 Database Entity Model
- `images`: Primary asset records (`id`, `url`, `filename`, `status`, `created_at`).
- `image_metadata`: Extracted attributes (`image_id`, `subject`, `category`, `attributes_json`, `caption`, `confidence`).
- `embeddings`: Dense numerical vectors (`entity_type`, `entity_id`, `vector_json`, `dimensions`).
- `posts`: Editorial articles (`id`, `title`, `slug`, `content`, `target_subject`, `created_at`).
- `suggestions`: Candidate pairings generated by matching engine (`post_id`, `image_id`, `similarity_score`, `guard_decision`, `explanation`, `rank`).
- `review_decisions`: Human feedback records (`suggestion_id`, `decision`, `reviewer_notes`, `decided_at`).
- `cost_log`: Token and cost accounting (`id`, `operation`, `model`, `prompt_tokens`, `completion_tokens`, `cost_usd`, `timestamp`).
- `batch_jobs`: Asynchronous processing state (`id`, `status`, `total_items`, `processed_items`, `failed_items`, `created_at`).

## 4. API Surface

| Endpoint | Method | Description |
| :--- | :--- | :--- |
| `/api/images` | `POST` | Ingest single image URL or trigger batch |
| `/api/images/batch` | `POST` | Asynchronous bulk processing of corpus |
| `/api/images/{id}` | `GET` | Retrieve image metadata, confidence status, and tags |
| `/api/posts` | `POST` | Create or update editorial article |
| `/api/posts/{id}/suggestions` | `GET` | Generate and return ranked images with Mismatch Guard checks |
| `/api/suggestions/{id}/review` | `POST` | Human review: approve or reject pairing |
| `/api/costs/summary` | `GET` | Aggregate token counts and budget status |
| `/api/eval/run` | `POST` | Execute precision benchmark against ground truth test set |

---

## 5. Explicit Non-Goals
- Real-time video frame extraction.
- End-user graphical dashboard (focused strictly on robust REST APIs, JSON verification, and CLI tooling).
- Unbounded vector dimensional indexing (optimized for deterministic local cosine evaluation on ~50-100 items).
